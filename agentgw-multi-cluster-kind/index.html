Solo Enterprise AgentGateway & Ambient Multicluster Mesh on Kind

TO
Tom O'Rourke
EMEA Field CTO · Solo.io

The ambient-multicluster-workshop flow on two kind clusters (east + west), with Solo Enterprise agentgateway replacing every Istio gateway type — enterprise-agentgateway for ingress, enterprise-agentgateway-waypoint for L7 and egress. No cloud account needed.

enterprise-agentgateway enterprise-agentgateway-waypoint Istio Ambient ztunnel HBONE MetalLB kind

This guide follows Ram Vennam's ambient-multicluster-workshop step for step, but replaces every Istio gateway type with Solo Enterprise agentgateway. The mesh fabric (ztunnel, HBONE, istiod) is unchanged — only the gateway layer swaps.

All steps use helm and kubectl inline — no wrapper scripts.

STEP 01

Create east-ag + west-ag kind clusters

The script reads $CLUSTER1 and $CLUSTER2, strips the kind- prefix to get the cluster name, and looks up the matching config in kind/. The -ag suffix means this demo can run alongside the istio-gw demo without name collisions.

./scripts/01-clusters.sh

Expected output:

  ✓ [east-ag] ready
  ✓ [west-ag] ready

Contexts available:
*  kind-east-ag   ← $CLUSTER1
   kind-west-ag   ← $CLUSTER2
STEP 02

Install MetalLB — LoadBalancer IPs on kind

Replaces the cloud LB. Detects the Docker kind network IPv4 CIDR at runtime and assigns non-overlapping pools. Pools are .100–.110 (east-ag) and .120–.130 (west-ag) — no overlap with the istio-gw demo's .200–.230 range.

./scripts/02-metallb.sh

Expected output:

  docker kind network: 172.22.0.0/16  (base: 172.22)
  ✓ [east-ag] MetalLB controller ready
  ✓ [west-ag] MetalLB controller ready
  ✓ MetalLB pools configured  (east-ag .100-.110  /  west-ag .120-.130)
Why MetalLB? cloud-provider-kind has a macOS bug where it fails to write the assigned IP back to status.loadBalancer.ingress. MetalLB works reliably on both macOS and Linux.

STEP 04

Configure trust — shared root CA

Both clusters share a root CA. Per-cluster intermediates are signed from it. The trust domain is locked to cluster.local on both clusters — the enterprise-agentgateway-waypoint binary hardcodes this and it must match.

Generate root CA

mkdir -p certs

openssl genrsa -out certs/root-ca.key 4096
openssl req -new -x509 -days 3650 \
  -key certs/root-ca.key \
  -subj "/O=Solo Demo/CN=Shared Root CA" \
  -out certs/root-ca.crt

Generate per-cluster intermediates

The SAN spiffe://cluster.local/ns/istio-system/sa/citadel is required — Solo Istio's cross-cluster cert-chain validation checks it.

for CTX in $CLUSTER1 $CLUSTER2; do
  N="${CTX#kind-}"
  openssl genrsa -out certs/${N}-ca.key 4096

  openssl req -new \
    -key certs/${N}-ca.key \
    -subj "/O=Solo Demo/CN=${N} Intermediate CA" \
    -out certs/${N}-ca.csr

  openssl x509 -req -days 3650 \
    -in  certs/${N}-ca.csr \
    -CA  certs/root-ca.crt \
    -CAkey certs/root-ca.key \
    -CAcreateserial \
    -extfile <(printf "subjectAltName=URI:spiffe://cluster.local/ns/istio-system/sa/citadel\nbasicConstraints=CA:TRUE\nkeyUsage=keyCertSign,cRLSign") \
    -out certs/${N}-ca.crt

  # cert-chain = intermediate + root
  cat certs/${N}-ca.crt certs/root-ca.crt \
    > certs/${N}-cert-chain.pem
done

Apply cacerts secrets

for CTX in $CLUSTER1 $CLUSTER2; do
  N="${CTX#kind-}"

  kubectl --context $CTX create namespace istio-system --dry-run=client -o yaml \
    | kubectl --context $CTX apply -f -

  kubectl --context $CTX -n istio-system create secret generic cacerts \
    --from-file=ca-cert.pem=certs/${N}-ca.crt \
    --from-file=ca-key.pem=certs/${N}-ca.key \
    --from-file=root-cert.pem=certs/root-ca.crt \
    --from-file=cert-chain.pem=certs/${N}-cert-chain.pem \
    --dry-run=client -o yaml | kubectl --context $CTX apply -f -
done

STEP 06

Install Solo Istio Ambient — Gloo Operator + ServiceMeshController

The Gloo Operator manages istiod + ztunnel + CNI as a single lifecycle. You declare what you want via a ServiceMeshController CR; the operator reconciles it.

Install Gloo Operator on both clusters

for CTX in $CLUSTER1 $CLUSTER2; do
  helm upgrade --install gloo-operator \
    oci://us-docker.pkg.dev/solo-public/gloo-operator-helm/gloo-operator \
    --kube-context $CTX \
    --namespace gloo-system --create-namespace \
    --version $GLOO_OPERATOR_VERSION \
    --wait
done

Create the Solo Istio licence secret

for CTX in $CLUSTER1 $CLUSTER2; do
  kubectl --context $CTX -n gloo-system create secret generic solo-istio-license \
    --from-literal=license="${SOLO_ISTIO_LICENSE_KEY}" \
    --dry-run=client -o yaml | kubectl --context $CTX apply -f -
done

Apply ServiceMeshController — east

kubectl --context $CLUSTER1 apply -f - <<EOF
apiVersion: operator.gloo.solo.io/v1
kind: ServiceMeshController
metadata:
  name: managed-istio
  namespace: gloo-system
spec:
  cluster: ${CLUSTER1#kind-}
  network: ${CLUSTER1#kind-}
  trustDomain: cluster.local
  version: "${ISTIO_VERSION_OPERATOR}"
  dataplaneMode: Ambient
  distribution: Standard
  scalingProfile: Demo
EOF

Apply ServiceMeshController — west

kubectl --context $CLUSTER2 apply -f - <<EOF
apiVersion: operator.gloo.solo.io/v1
kind: ServiceMeshController
metadata:
  name: managed-istio
  namespace: gloo-system
spec:
  cluster: ${CLUSTER2#kind-}
  network: ${CLUSTER2#kind-}
  trustDomain: cluster.local
  version: "${ISTIO_VERSION_OPERATOR}"
  dataplaneMode: Ambient
  distribution: Standard
  scalingProfile: Demo
EOF

Wait for istiod to be ready

for CTX in $CLUSTER1 $CLUSTER2; do
  kubectl --context $CTX -n istio-system wait \
    --for=condition=Available deployment/istiod-gloo \
    --timeout=300s
done

Patch mesh components — required env vars for Ambient peering

The Solo Istio Ambient multicluster manual install guide sets these via platforms.peering.enabled: true in the istiod and ztunnel Helm values, which wires them automatically. The Gloo Operator 0.5.2 SMC schema doesn't expose that flag yet, so we apply the two required vars directly:

  • PILOT_ENABLE_K8S_SELECT_WORKLOAD_ENTRIES=false on istiod — enables Ambient endpoint rewriting (cross-cluster endpoints resolve via east-west gateway, not K8s WorkloadEntries)
  • L7_ENABLED=true on ztunnel — enables L7-aware HBONE tunnelling through waypoints
# istiod — disable K8s WorkloadEntry selection (required for cross-cluster endpoint rewriting)
for CTX in $CLUSTER1 $CLUSTER2; do
  kubectl --context $CTX -n istio-system patch deployment istiod-gloo \
    --type=json -p='[
      {"op":"add","path":"/spec/template/spec/containers/0/env/-",
       "value":{"name":"PILOT_ENABLE_K8S_SELECT_WORKLOAD_ENTRIES","value":"false"}}
    ]'
done

# ztunnel — enable L7-aware HBONE (required for waypoint traffic across clusters)
for CTX in $CLUSTER1 $CLUSTER2; do
  kubectl --context $CTX -n istio-system patch daemonset ztunnel \
    --type=json -p='[
      {"op":"add","path":"/spec/template/spec/containers/0/env/-",
       "value":{"name":"L7_ENABLED","value":"true"}}
    ]'
done

# Wait for rollouts
for CTX in $CLUSTER1 $CLUSTER2; do
  kubectl --context $CTX -n istio-system rollout status deployment/istiod-gloo --timeout=120s
  kubectl --context $CTX -n istio-system rollout status daemonset/ztunnel --timeout=120s
done

Create istiod alias Service

The enterprise-agentgateway-waypoint binary hardcodes CA_ADDRESS=istiod.istio-system.svc:15012 but Gloo Operator names the deployment istiod-gloo.

for CTX in $CLUSTER1 $CLUSTER2; do
  kubectl --context $CTX apply -f - <<'EOF'
apiVersion: v1
kind: Service
metadata:
  name: istiod
  namespace: istio-system
spec:
  selector:
    app: istiod
  ports:
  - name: grpc-xds
    port: 15010
  - name: https-dns
    port: 15012
  - name: https-webhook
    port: 443
    targetPort: 15017
EOF
done
STEP 07

Peer clusters — east-west HBONE gateways

This installs the Istio east-west gateway on each cluster (the HBONE mesh fabric). The enterprise agentgateway waypoint sits on top of this at L7 — it does not replace it.

Kind has no cloud LB for this. The east-west gateway uses NodePort (fixed ports 30015/30016) instead of LoadBalancer. Remote peers reference the kind control-plane node IP directly.

Label istio-system with the cluster network

Without this label istiod can't classify remote pod networks and endpoint rewriting never fires.

kubectl --context $CLUSTER1 label ns istio-system topology.istio.io/network=${CLUSTER1#kind-} --overwrite
kubectl --context $CLUSTER2 label ns istio-system topology.istio.io/network=${CLUSTER2#kind-} --overwrite

Install east-west gateway — east cluster

kubectl --context $CLUSTER1 create namespace istio-eastwest --dry-run=client -o yaml \
  | kubectl --context $CLUSTER1 apply -f -

helm upgrade --install peering-eastwest \
  oci://us-docker.pkg.dev/soloio-img/istio-helm/peering \
  --kube-context $CLUSTER1 \
  --namespace istio-eastwest \
  --version $ISTIO_VERSION \
  --set eastwest.create=true \
  --set eastwest.cluster=${CLUSTER1#kind-} \
  --set eastwest.network=${CLUSTER1#kind-} \
  --set 'eastwest.dataplaneServiceTypes[0]=nodeport' \
  --set eastwest.service.spec.type=NodePort \
  --set 'eastwest.service.spec.ports[0].name=tls-hbone' \
  --set 'eastwest.service.spec.ports[0].port=15008' \
  --set 'eastwest.service.spec.ports[0].nodePort=30015' \
  --set 'eastwest.service.spec.ports[0].protocol=TCP' \
  --set 'eastwest.service.spec.ports[1].name=tls-xds' \
  --set 'eastwest.service.spec.ports[1].port=15012' \
  --set 'eastwest.service.spec.ports[1].nodePort=30016' \
  --set 'eastwest.service.spec.ports[1].protocol=TCP' \

STEP 08

Enable Istio Ambient for bookinfo namespace

Labelling the namespace enrolls all its pods in the Ambient data plane (ztunnel intercepts traffic at L4). No pod restarts needed.

for CTX in $CLUSTER1 $CLUSTER2; do
  kubectl --context $CTX label namespace bookinfo \
    istio.io/dataplane-mode=ambient \
    topology.istio.io/network=${CTX#kind-} \

done

STEP 09

Enable productpage as a multi-cluster global service

Label productpage on both clusters so istiod merges endpoints across clusters. Traffic distributes to whichever cluster has a healthy pod.

for CTX in $CLUSTER1 $CLUSTER2; do
  kubectl --context $CTX label svc productpage -n bookinfo \
    solo.io/service-scope=global \
    --overwrite
  kubectl --context $CTX annotate svc productpage -n bookinfo \
    networking.istio.io/traffic-distribution=Any \
    --overwrite
done
Two scope options: solo.io/service-scope=global — prefer local, spill to remote if local is down. solo.io/service-scope=global-only — always load-balance across both clusters regardless of locality.

STEP 11

Expose productpage — enterprise-agentgateway ingress

Replaces the upstream workshop's gatewayClassName: istio Gateway. Deploy to $CLUSTER1 — this is where you'll access bookinfo from.

Same YAML shape as the upstream workshop — only gatewayClassName changes. The HTTPRoute and listener structure are identical. 
kubectl --context $CLUSTER1 apply -f - <<'EOF'
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: bookinfo-gateway
  namespace: bookinfo
spec:
  gatewayClassName: enterprise-agentgateway   # ← was "istio"
  listeners:
  - name: http
    port: 8080
    protocol: HTTP
    allowedRoutes:
      namespaces:
        from: Same
---
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: productpage
  namespace: bookinfo
spec:
  parentRefs:
  - name: bookinfo-gateway
  rules:
  - backendRefs:
    - name: productpage
      port: 9080
EOF

  port-forward svc/bookinfo-gateway 8080:8080 &

curl -s http://localhost:8080/productpage | grep -o "<title>.*</title>"
# → <title>Simple Bookstore App</title>

# Kill port-forward when done
kill %1
If you're running on Linux (or Docker Desktop with network tunnel), curl http://${GATEWAY_IP}:8080/productpage works directly.
STEP 12

Failover — scale productpage down on east

Demonstrates cross-cluster failover. Traffic should continue to flow to west's productpage when east's is scaled to zero.

Scale down productpage on east

kubectl --context $CLUSTER1 scale deploy productpage-v1 -n bookinfo --replicas=0

# Wait, then curl — traffic should still arrive via west
kubectl --context $CLUSTER1 -n bookinfo \
  port-forward svc/bookinfo-gateway 8080:8080 &
curl -s http://localhost:8080/productpage | grep -o "<title>.*</title>"
kill %1

Scale back up

kubectl --context $CLUSTER1 scale deploy productpage-v1 -n bookinfo --replicas=1

Bonus — force details failover

Labels details as global-only so load balances equally across both clusters even when both are up.

kubectl --context $CLUSTER1 scale deploy details-v1 -n bookinfo --replicas=0

kubectl --context $CLUSTER1 label svc details -n bookinfo \
  solo.io/service-scope=global-only --overwrite

# curl productpage on east — details are served from west
kubectl --context $CLUSTER1 -n bookinfo \
  port-forward svc/bookinfo-gateway 8080:8080 &
curl -s http://localhost:8080/productpage | grep "Book Details"
kill %1

# Restore
kubectl --context $CLUSTER1 scale deploy details-v1 -n bookinfo --replicas=1
STEP 13

L7 policy — enterprise-agentgateway-waypoint

Replaces gatewayClassName: istio-waypoint. Deploy the waypoint to the bookinfo namespace, then apply an HTTPRoute to control reviews traffic.

Same YAML shape as the upstream workshop — gatewayClassName and port change; everything else is identical.
Port 15088 is the inbound application listener for the enterprise waypoint (vs 15008 HBONE termination).

Deploy enterprise-agentgateway-waypoint

kubectl --context $CLUSTER1 apply -f - <<'EOF'
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: waypoint
  namespace: bookinfo
  labels:
    istio.io/waypoint-for: namespace
spec:
  gatewayClassName: enterprise-agentgateway-waypoint   # ← was "istio-waypoint"
  listeners:
  - name: mesh
    port: 15088                                          # ← was 15008
    protocol: HTTP
EOF

Label namespace to use this waypoint

kubectl --context $CLUSTER1 label namespace bookinfo \
  istio.io/use-waypoint=waypoint --overwrite

Apply reviews v1 routing (header-based)

Sends user jason to reviews-v2 (with ratings stars); everyone else gets reviews-v1 (no stars).

kubectl --context $CLUSTER1 apply -f - <<'EOF'
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: reviews
  namespace: bookinfo
spec:
  parentRefs:
  - group: ""
    kind: Service
    name: reviews
    port: 9080
  rules:
  - matches:
    - headers:
      - name: end-user
        value: jason
    backendRefs:
    - name: reviews-v2
      port: 9080
  - backendRefs:
    - name: reviews-v1
      port: 9080
EOF

Test — default user (no stars)

kubectl --context $CLUSTER1 -n bookinfo \
  port-forward svc/bookinfo-gateway 8080:8080 &
curl -s http://localhost:8080/productpage | grep "glyphicon-star"
# → no output (reviews-v1, no stars)
kill %1

Test — user jason (black stars)

kubectl --context $CLUSTER1 -n bookinfo \
  port-forward svc/bookinfo-gateway 8080:8080 &
curl -s -H "end-user: jason" http://localhost:8080/productpage \
  | grep "glyphicon-star"
# → should find star elements (reviews-v2)
kill %1

Clean up routing

kubectl --context $CLUSTER1 delete httproute reviews -n bookinfo
kubectl --context $CLUSTER1 label namespace bookinfo \
  istio.io/use-waypoint- --overwrite
STEP 14

Egress gateway — enterprise-agentgateway-waypoint

Controls which workloads can reach external services. Replaces gatewayClassName: istio-waypoint in the egress namespace.

Create namespace and deploy egress gateway

kubectl --context $CLUSTER1 create namespace istio-egress

kubectl --context $CLUSTER1 apply -f - <<'EOF'
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: egress-gateway
  namespace: istio-egress
  labels:
    istio.io/waypoint-for: service
spec:
  gatewayClassName: enterprise-agentgateway-waypoint   # ← was "istio-waypoint"
  listeners:
  - name: mesh
    port: 15088                                          # ← was 15008
    protocol: HTTP
    allowedRoutes:
      namespaces:
        from: All
EOF

kubectl --context $CLUSTER1 label ns istio-egress \
  istio.io/use-waypoint=egress-gateway

Define httpbin.org as an external service and apply AuthorizationPolicy

kubectl --context $CLUSTER1 apply -f - <<'EOF'
apiVersion: networking.istio.io/v1
kind: ServiceEntry
metadata:
  name: httpbin.org
  namespace: bookinfo
  labels:
    istio.io/use-waypoint: egress-gateway
    istio.io/use-waypoint-namespace: istio-egress
spec:
  hosts:
  - httpbin.org
  ports:
  - number: 80
    name: http
    protocol: HTTP
    targetPort: 443
  resolution: DNS
---
apiVersion: networking.istio.io/v1
kind: DestinationRule
metadata:
  name: httpbin.org-tls
  namespace: bookinfo
spec:
  host: httpbin.org
  trafficPolicy:
    tls:
      mode: SIMPLE
---
apiVersion: security.istio.io/v1
kind: AuthorizationPolicy
metadata:
  name: ratings-to-httpbin
  namespace: bookinfo
spec:
  targetRefs:
  - kind: ServiceEntry
    group: networking.istio.io
    name: httpbin.org
  action: ALLOW
  rules:
  - from:
    - source:
        principals:
        - "cluster.local/ns/bookinfo/sa/bookinfo-ratings"
EOF

Test — ratings should succeed

kubectl --context $CLUSTER1 exec -it \
  $(kubectl --context $CLUSTER1 get pod -l app=ratings -n bookinfo \
    -o jsonpath='{.items[0].metadata.name}') \
  -n bookinfo -- curl -s httpbin.org/get | head -5

Test — reviews should be blocked

kubectl --context $CLUSTER1 exec -it \
  $(kubectl --context $CLUSTER1 get pod -l app=reviews -n bookinfo \
    -o jsonpath='{.items[0].metadata.name}') \
  -n bookinfo -- curl -sv httpbin.org/get 2>&1 | grep -E "RBAC|403|denied"

Teardown

kind delete cluster --name east-ag
kind delete cluster --name west-ag
rm -rf certs/
